## How we work

- Run the prompts below **in order**, one per session turn. The user types `Run P07` (or similar).
- Work as an expert data scientist: state assumptions, check the data before modelling, and report uncertainty (CIs, sensitivity). Never claim causation (brief §5, "What you won't claim").
- **After every prompt:** (1) list every figure created, with its path, and show it (Read the PNG); (2) give 3–5 bullet findings or numbers; (3) ask any questions that came up; (4) tick the prompt below as `- [x] ✅ DONE! **Pxx: …** _Done YYYY-MM-DD: one-line result._` and add "✅ DONE" to a phase heading once all its prompts are done. Also update the **Progress** list at the top: add a `✅ DONE! Pxx` line and move the `← next` marker.
- Figures: `figures/pNN_<name>.png` (static, 200 dpi) and, for the hero and interactive charts, `.html` as well. Every figure uses `src/lw/viz/theme.py`. Each figure must work as a standalone image: title, units (LUFS, LU), n, and source line ("Data: AcousticBrainz + MusicBrainz, CC0").
- Data layout: `data/raw/` (downloads, git-ignored), `data/interim/` (Parquet), `data/processed/` (analysis tables), `data/reference/` (hand-built, committed). Big dumps are **streamed and parsed on the fly, never stored whole** (240 GB free disk).
- Stack: Python 3.12 via `uv`, polars + DuckDB for data, pyarrow Parquet, statsmodels / PyMC for models, matplotlib (static) + Plotly or Observable (interactive), Quarto for the report, pytest for tests.
- Every pipeline step is a `make` target and is idempotent. Pin key numbers (row counts, medians) in tests once they are known.
- Commit after each prompt with message `Pxx: <summary>`.

## Decisions (defaults; update if the user changes them)

- **Metrics (changed at P01, 2026-11-02):** AcousticBrainz has **no `loudness_ebu128`** (every record comes from the Essentia `music 1.0` extractor). Headline loudness = **calibrated loudness (≈ LUFS) from `audio_properties.replay_gain`**; dynamics = **`lowlevel.dynamic_complexity`** (LRA analogue), plus `average_loudness`. P03 calibrates both against pyloudnorm LUFS/LRA. Charts label the measure "estimated LUFS" and give the calibration error. See `notes/p01_access_check.md`. **The user approved this on 2026-11-02**, along with installing Rosetta for the original extractor and running P05 before P02.
- Core sample: release years 1980–2022, tracks with valid `replay_gain` and `dynamic_complexity`. The 100k sample dump ends in 2014 and is used **only** for fixtures and tests.
- Dump parts 0–29 are in submission order (part 0 ≤ 2014; later parts reach 2022), so all 30 parts are needed.
- Headline break year: 2015, with 2013–2017 as alternatives. (P04: report 2016 alongside 2015, since the era starts Dec 2015 and release years are whole years.)
- "Lossless" = FLAC/ALAC/WAV/AIFF; lossy is flagged and dropped in robustness checks.
- Genre: MusicBrainz release-group tags mapped to 12 top-level genres (`data/reference/genre_map.csv`; blues → "R&B / soul / blues"). **Changed at P10:** fallbacks are release → recording → **artist tags** (68% agreement with rg genre) → AcousticBrainz rosamerica classifier (33%, `genre_source = 'hl'`, flagged). **P15 excludes `hl` units (user decision 2026-11-07)**; including them is a sensitivity check only. `make dedupe` drops the genre columns, so `make genres` must follow it.
- Ingest scale: **stream the full low-level dumps** (user decision, 2026-11-02).
- **Headline sample (user decision, 2026-11-05): lossless units only.** P12/P13 use `in_main_lossless` (main sample with ≥1 lossless submission: 2,997,479 units, 771k in 2015–2022; 2,997,536 before the 2026-11-07 tag exclusions); the dashed comparison is **all codecs excluding units whose loudness comes from a ≤160 kbps lossy copy** (user decision 2026-11-07; drops 21.4% of `in_main`, 38.1% of 2015–2022, up to ~50% in 2020–21; the headline loses none). This reverses the original "lossy dropped in robustness checks" default.
- **Gain tags (user decision, 2026-11-05; done 2026-11-07):** re-stream finished (30/30 parts, 29,460,584 rows). Gain tags exist only in dump part 0, and the `mp3gain_undo` correction leaves a −5 LU residual, so MP3Gain-tagged and named stream-rip lossy files are **excluded** (`gain_tagged` 9,606, `stream_rip` 45,315), not corrected; headline sample now 2,997,479. The 2014+ lossy gap is a **bitrate-mix effect** (≤160 kbps copies read −0.44 LU in every year since 2007, >160 kbps −0.04 LU; low-bitrate share rose to ~50%), not streaming or mastering. P19 adds a "drop ≤160 kbps lossy" spec. See `notes/p09_dedupe.md`.
- **Unit loudness (P09): lossless first.** `lufs`/`lra` = median over a unit's lossless submissions if it has any, else its lossy ones; some lossy files had MP3Gain/aacgain applied (identical audio, level shifted). `lufs_all`, `lufs_lossless`, `lufs_lossy` are kept. Lossy copies read ~0.4 LU quieter than lossless from 2014 on (a bitrate-mix effect, see Gain tags), so the lossless-only check is essential in P12/P13/P19.
- Reissue rule (P08): deluxe / special edition / bonus tracks are `is_deluxe`, **not** reissues (86% are released with the original); reissue keywords are remaster, anniversary, reissue, legacy edition, expanded.
- Own audio: **some rips, mostly lossy** (user decision, 2026-11-02). P18 treats them as secondary evidence, and the R128 test signals plus published measurements serve as the main check. P03 used `~/Music/iTunes/iTunes Media/Music` + `~/Music/Music` (AAC). **Update 2026-11-05:** the user will rip ~12 CDs to FLAC/ALAC with MusicBrainz IDs (quiet pre-1990, loud-war peak, post-2015, classical/jazz, metal/EDM, plus an original + remaster pair if possible) for P18.
